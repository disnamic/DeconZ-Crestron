Version 3.1.0  (2026-05-25)
--------------------------------------------------------------------------------
New modules: DeConzMotion, DeConzPower, DeConzAlarm. Suite now 14 modules.

DeConzMotion – Presence + light level sensor:
  - ZHAPresence endpoint: presence_fb, tampered_fb.
  - ZHALightLevel endpoint: lux_fb, lightlevel_fb, dark_fb, daylight_fb.
  - Configurable via HTTP PUT config: duration (presence timeout),
    tholddark and tholdoffset (light level thresholds for dark/daylight flags).
  - State fetched on WS connect/reconnect (random 1-15 s). No background poll.
  - Optional ZHABattery endpoint. All three UIDs are optional.
  - 5 parameters → 5 SKIP. 18 delegates.

DeConzPower – Smart plug / power meter:
  - Three optional endpoints: switch (on/off light), ZHAPower, ZHAConsumption.
  - Switch: Set_On / Set_Off commands + on_fb / off_fb feedback.
  - ZHAPower: Power_fb (W), Voltage_fb (V), Current_fb (A).
  - ZHAConsumption: Consumption_fb (Wh), Consumption_Power_fb (W).
  - Note: consumption is a hardware counter; reset not possible via deCONZ API.
    Implement a software offset in SIMPL+ for reset functionality.
  - 5 parameters → 5 SKIP. 18 delegates.

DeConzAlarm – Alarm / fire / CO safety sensors:
  - Three optional endpoints: ZHAAlarm, ZHAFire, ZHACarbonMonoxide.
  - Shared: tampered_fb, battery_low, battery_level, online timer.
  - Suitable for single-type detectors and combination devices (all three UIDs).
  - Optional ZHABattery endpoint.
  - 6 parameters → 6 SKIP. 17 delegates.

Group and Scene modules: added full CRUD and management functions.
  - DeConzGroupControl: CreateGroup, SetName, SetMembers, GetAllGroups,
    plus DeleteGroup (v3.0). New outputs: Create_success_fb, New_Group_Id_fb,
    Set_Attr_success_fb, all_groups_fb, Members_In and New_Group_Name inputs.
  - DeConzScene: CreateScene, DeleteScene, SetSceneName, GetSceneAttr.
    New outputs: Create_Success_fb, Delete_Success_fb, Set_Attr_Success_fb,
    New_Scene_Id_fb, scene_attr_fb. New input: New_Scene_Name.

Version 3.0.0  (2026-05-26)   *** FIRST PUBLIC RELEASE ***
--------------------------------------------------------------------------------
First publicly released version of the DeConz Zigbee SIMPL# module suite.

This release consolidates the complete module set and all fixes accumulated
during private development into a stable, documented public package.

Included modules (11):
  Gateway, Device, Keypad, Light_WS, Valve, Shade, Thermostat,
  Climate, Contact, Group_Control, Scene.
Supporting infrastructure:
  DeConzBroker (static multicast bus), DeConzJsonParser (shared parser),
  DeConzWebSocketClient (RFC-6455 gateway connection).

Changes in this release:
  - Signed temperature output fix (Climate, Thermostat):
    The Temperature_fb analog output now carries negative temperatures as a
    16-bit two's-complement value, to be read as a signed analog in SIMPL
    (e.g. -5.0 C → 65036). Previously negative temperatures were clamped to 0.
    The Temperature_str string output was and remains correct for all values.
    Humidity and pressure are unsigned and unchanged.
  - Documentation rewritten in English, restructured, and brought up to date
    for all 11 modules.

Version 2.19.0  (2026-05-24)
--------------------------------------------------------------------------------
Memory management: fixed fire-and-forget CTimer leak (critical code review).
  - 12 one-shot CTimer instances across 8 modules were created without being
    stored or disposed (ScheduleGetState/ScheduleGet stagger timers and
    Scene success pulses).
  - Crestron CTimer is IDisposable and holds an internal .NET timer +
    callback delegate; one-shot timers do not free themselves after firing.
  - Fix: each one-shot timer is now held in a local variable and disposes
    itself at the end of its callback:
      CTimer t = null;
      t = new CTimer(_ => { Work(); if (t != null) t.Dispose(); }, null, delay);
  - Affected: Climate, Contact (×2), Keypad, LightWs, Scene (×2),
    Shade (×2), Thermostat (×2), Valve.
  - Stored timers (_onlineTimer, _pollTimer, _brightnessTimer, _moveTimer,
    _aliveTimer, _reconnectTimer) were already correctly stopped/nulled and
    are unchanged.

Code review notes (no change required):
  - Dispose() methods exist and are symmetric (Register/Unregister balanced)
    but are not called by SIMPL+ wrappers. Acceptable: SIMPL# objects live
    for the whole program lifetime; AppDomain unload frees everything on
    program restart. Methods retained for completeness.
  - HttpClient is a long-lived readonly instance per module – this is the
    recommended usage pattern, not a leak.
  - WebSocketClient socket cleanup correctly removes event handlers (-=) and
    nulls references in CloseSocket().

Version 2.18.1  (2026-05-24)
--------------------------------------------------------------------------------
Fixed CS1503 compile errors in DeConzScene, DeConzGroupControl, DeConzClimate.
  - DispatchAsync() requires Crestron's HTTPClientResponseCallback delegate,
    not a generic Action<HttpClientResponse, HTTP_CALLBACK_ERROR>.
  - Lambda callbacks passed to DispatchAsync (e.g. "(resp,err) => OnFoo(s,…)")
    are incompatible with this type and cause CS1503.
  - Fix: replaced lambdas with named callbacks matching the Crestron signature.
    Slot / context captured in instance fields (_pendingHttpSlot,
    _pendingRecallGroup/_Scene, _lastActionSlot) set before DispatchAsync.
  - All CS files scanned – no remaining lambda-at-DispatchAsync patterns.

New modules: DeConzGroupControl, DeConzScene.

  - 10 delegates.

DeConzScene – deCONZ scene recall and store:
  - Group_ID and Scene_ID set at runtime via ANALOG_INPUT.
  - Recall_Scene: PUT /groups/<G>/scenes/<S>/recall

  - Get_Scenes:   GET /groups/<G>/scenes → scenes_list_fb ("1:warmlight,2:reading")
  - Recall_Success_fb / Store_Success_fb: 200 ms pulse on HTTP 200 OK.
  - Last_Recalled_Group_fb / Last_Recalled_Scene_fb: analog feedback.
  - Pure HTTP module – no WebSocket / broker registration.
  - 7 delegates.

Both modules:
  - Only API_Key as parameter → 1 _SKIP_ before first signal.
  - Enable_Raw_Json digital input (consistent with all other modules).
  - GatewayIP read from DeConzBroker (no IP parameter needed).

  - Raw JSON output is now disabled by default (default = 0).
  - Pulse/hold Enable_Raw_Json high to activate raw_json_out and all other

  - Modules with multiple raw JSON outputs (Valve: 2, Thermostat: 2,

  - Implemented as _rawJsonEnabled flag checked in FireRawJson/FireRaw before
    any raw JSON delegate is invoked.

Wrapper signal layout rule applied:
  - Number of _SKIP_ before first I/O signal = number of parameters,
    so signals appear below the parameter fields in SIMPL Windows.

DeConzLightWs: Brightness feedback fixed (was not updating on SetBrightness).

  - Now uses on-state from the current event when available, falls back to

Version 2.16.3  (2026-05-23)
--------------------------------------------------------------------------------
CRITICAL: Fixed regression introduced in v2.16.2 where the parser-block
removal script deleted business logic methods alongside the private parser
methods. DeConzValve, DeConzShade and DeConzThermostat were non-compilable.

Restored methods in affected classes:
  DeConzValve       – ParseValveState, ParseSensorState, ParseDeviceInfo,
                      RestartOnlineTimer, StopOnlineTimer
  DeConzShade       – ParseState, ParseDeviceInfo, ScheduleGetState,
                      RestartOnlineTimer, StopOnlineTimer
  DeConzThermostat  – ParseState, ParseConfig, ParseDeviceInfo,
                      ParseBatteryState, RestartOnlineTimer, StopOnlineTimer

Additional improvements included in this release:
  - DeConzThermostat: ExtractBlock() to isolate state{} vs config{} objects,
    preventing state.on from being read when config.on is intended (both at
    depth 2, same key name).
  - DeConzJsonParser: NextStaggerMs() added (shared static Random with lock),
    replaces all per-call new Random() instances that could produce identical
    delays when called simultaneously on reconnect.
  - DeConzWebSocketClient: permessage-deflate extension removed from WS
    handshake offer. The frame decoder cannot handle compressed payloads;
    advertising the extension risked the server sending compressed frames.
  - TOCTOU guards added to BuildUrls() in all modules (prevents double URL
    construction on concurrent threads).
  - Range guards for thermostat setpoints (500–3500 = 5.0–35.0°C) reject
    SIMPL+ startup zero-signals.
  - InvariantCulture used for temperature/offset string formatting instead
    of manual comma-to-dot replacement.

Version 2.0.0  (2026-05-20)  [initial SIMPL# rewrite]
--------------------------------------------------------------------------------
Full rewrite of original SIMPL+ deCONZ gateway as SIMPL# module suite.

DeConzBroker (static class):
  - Central message bus; routes WS payloads to registered device modules.
  - No signal wiring between Gateway and device modules required.
  - GatewayIP property for HTTP URL construction by device modules.
  - Thread-safe dispatch via CrestronInvoke.BeginInvoke.

DeConzWebSocketClient:
  - Native RFC-6455 WebSocket (TCP via CrestronTCP / SecureTCPClient for TLS).
  - Full frame decoder: fin/opcode/mask/payload length (including 16- and
    64-bit extended lengths).
  - Exponential back-off reconnect (5 s → 30 s max).
  - Ping/Pong keepalive.
  - TLS/WSS support via Use_TLS parameter.
  - Traffic-present indicator with configurable alive timeout.

DeConzDevice:
  - Raw JSON passthrough; forwards WS payloads to SIMPL+ raw_json_out.
  - Registers with broker by uniqueid (no slot index required initially).

Improvements over original SIMPL+ module:
  - Reconnect logic: none → exponential back-off
